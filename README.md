# NULLCAM plugins

Three boutique VST3 plugins from the NULLCAM family, built with JUCE 8 and C++17.

| Plugin | What it is | State |
|---|---|---|
| **PIER-MODE** | The audio damage of the NULLCAM app as a live chain: band pass → crush → echo → ring mod, with a dry branch that keeps the core of the sound. | ready — Windows + macOS |
| **MAURI-MODE** | Rhythm slicer. The pattern is not written by hand: it is generated by the dynamics of what you are playing (a Boss Slicer fed by your own playing). | ready — Windows + macOS |
| **SPAMPI-MODE** | Sampler + Rainbow Machine in one: real CC0 recordings are re-pitched by the pitch detected in real time from your input audio, with no MIDI involved. | in progress |

Every plugin is a VST3 (plus a Standalone app on Windows). Audio Units are not
shipped, on purpose: one bundle to install is one thing less to explain.

---

## Repository layout

```
PIER-MODE/          plugin 1 (CMakeLists.txt, Source/, tests/, docs/)
MAURI-MODE/         plugin 2
SPAMPI-MODE/        plugin 3
tools/              shared build and packaging scripts for macOS
.github/workflows/  GitHub Actions: macOS VST3 build
```

Each plugin is self-contained: its own `CMakeLists.txt`, its own engine, its own
tests, its own fonts. `tools/` only knows how to build and pack them for macOS.

## Building on Windows

Requirements: Visual Studio 2022 (desktop development with C++), CMake 3.22+,
Git. JUCE is cloned automatically on the first configure; point `-DJUCE_DIR=`
at an existing checkout to skip the download.

```powershell
cd PIER-MODE
cmake -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release --target NullcamChain_VST3 NullcamChain_Standalone
```

The same two commands work in `MAURI-MODE` (targets `MauriMode_VST3`,
`MauriMode_Standalone`). The bundle is copied after the build into
`%LOCALAPPDATA%\Programs\Common\VST3` — no administrator rights needed — or
into the system folder when the build runs elevated.

The DSP of each plugin is framework-free and has its own test target:

```powershell
cmake --build build --config Release --target nullcam_dsp_test
build\Release\nullcam_dsp_test.exe
```

## Building macOS from a Windows machine

There is no macOS toolchain on the author's machine, so the macOS bundles are
built by **GitHub Actions on Apple's own machines** and come back as a
universal binary.

```
.github/workflows/macos-vst3.yml
        │
        ├─ prepare   scans the plugins, builds the matrix (tools/scan-plugins.sh)
        ├─ build     macos-15-intel (x86_64) + macos-15 (arm64), one job per plugin/arch
        └─ package   lipo → one universal .vst3 → ad-hoc codesign → zip
```

The finished artefact is `PIER-MODE-macOS-VST3.zip` (and the same for
MAURI-MODE): it contains the universal `*.vst3` bundle and
`LEGGIMI - installazione macOS.md`, the guide for whoever receives it.

To produce them:

1. push this repository to GitHub;
2. open the **Actions** tab → **macOS VST3** → **Run workflow** (it also runs
   automatically on every push to `main`);
3. when the run is green, download the `<PLUGIN>-macOS-VST3` artefact.

A plugin without a `CMakeLists.txt` or without `Source/PluginProcessor.cpp` is
skipped by `tools/scan-plugins.sh`, so a half-finished plugin never breaks the
matrix. The script can be run locally to preview the matrix:

```bash
./tools/scan-plugins.sh
```

### Gatekeeper

The bundles are **ad-hoc signed, not notarised**: a Developer ID certificate
costs money, and without it macOS may still ask the user to confirm the plugin
the first time it is opened. The install guide inside the zip explains both
the Finder route (no Terminal) and the one-line `xattr` fallback.

## Installing

- **Windows** — copy the `.vst3` into `%LOCALAPPDATA%\Programs\Common\VST3`
  (or `C:\Program Files\Common Files\VST3` for all users), then rescan the
  plug-ins in the DAW.
- **macOS** — copy the whole `*.vst3` folder into
  `~/Library/Audio/Plug-Ins/VST3`, then *Ableton → Settings → Plug-Ins →
  Rescan*.

---

## Presets

Factory presets are built into the binary. User presets are XML files, one
file per preset, so they survive a reinstall and can be copied around:

| Plugin | Windows | macOS |
|---|---|---|
| PIER-MODE | `%APPDATA%\NULLCAM\PIER-MODE\presets` | `~/Library/Application Support/NULLCAM/PIER-MODE/presets` |
| MAURI-MODE | `%APPDATA%\NULLCAM\MAURI-MODE\presets` | `~/Library/Application Support/NULLCAM/MAURI-MODE/presets` |
| SPAMPI-MODE | `%APPDATA%\NULLCAM\SPAMPI-MODE\presets` | `~/Library/Application Support/NULLCAM/SPAMPI-MODE/presets` |

The DAW project saves the knobs on its own, independently of these files.

## Licences

- **Code** — JUCE is used under its **AGPLv3 / commercial dual licence**. As long as the
  plugins are distributed under the AGPLv3, the complete corresponding source has to
  travel with them: this public repository is that source, so the zips sent to
  anybody must point back to it (the `LEGGIMI` inside every zip does). If the code
  should ever stay closed or the plugins should be sold, a **commercial JUCE
  licence** is required — the open source route does not allow that.
- **Fonts** — SIL Open Font License, shipped inside each plugin
  (`Source/Fonts/OFL.txt`).
- **SPAMPI-MODE samples** — the bundled recordings are **CC0** (public domain
  dedication), so they can be redistributed inside the plugin. The provenance
  table (source, author, licence) is in `SPAMPI-MODE/SAMPLES.md`.

## The faceplates

The panels are typographic boutique-pedal plates: matte black paper, acid
colours, knurled knobs, real numeric read-outs you can click and type into.
The fonts travel inside the binary, so the panel looks the same on every
machine. PIER-MODE and MAURI-MODE use Bungee / Bungee Shade; SPAMPI-MODE uses
the gummy **Bagel Fat One** with rainbow accents.
